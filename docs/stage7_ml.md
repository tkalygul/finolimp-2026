# Этап 7: модель риска

Полный запуск: `python reconcile.py --data data_2_final --out out/report`.
Отдельно после этапов сверки/классификации: `python -m src.ml_risk --interim interim`.
Независимая разметка: `--verified-labels labels.csv` (оба запуска).
CSV: match_id,is_error,error_owner,is_verified. is_error=0/1; error_owner=none,
bot,agent,1c,unclear; is_verified=true/1/yes. Неподтвержденные строки не используются.
При ручной разметке обучение и проверка используют только подтвержденные строки.

Две регуляризованные логистические модели реализованы на NumPy: риск ошибки
и источник при наличии ошибки. Метки по умолчанию — слабая разметка правил:
none=0, bot/agent/1c=1, unclear исключается, а не становится отсутствием ошибки.
confidence и assignment_status не подтверждают истинность финансовой ошибки.
Метрики rule_proxy измеряют воспроизведение правил; для заявления качества
реальных ошибок нужны независимо проверенные метки. Вероятности не откалиброваны.

Признаки: наличие источников, знаки и log суммы нормализованного долга,
неизвестность суммы, число исходных строк, виды операций, создатель ETM,
число билетов, день недели/месяца. Нет имен сотрудников/субагентов, ID, типа
ошибки, is_error, владельца, confidence, flags, предложений корректировки.
Признаки используют данные после загрузки/сверки, не прогноз до появления операции.

Проверка: последний месяц целиком отложен; обучение — до его начала.
Одна группа не попадает в обе части. Группы с неизвестной датой и пересекающие
границу исключаются. Масштабирование обучается только на train. Test не участвует
в обучении, подборе признаков/порогов и последующем дообучении сохраненной модели.
Нет случайного разбиения частей многобилетных строк.

Метрики: accuracy, precision/recall/F1 по классам, macro F1 и матрицы ошибок;
для бинарной модели также ROC AUC, average precision, Brier score. При одном
классе test ROC AUC/AP отсутствуют. Базовые прогнозы: распространенность ошибки
в train и наиболее частый источник train. Неподдерживаемые источники указаны
явно: ноль означает отсутствие обучающих примеров, не доказанную безопасность.

При отсутствии достаточной выборки/двух месяцев/двух бинарных классов запуск
завершается с объяснением, не сообщает выдуманный успех.

Выход interim/ml: model.json (веса, масштабирование, признаки, SHA256 входов),
metrics.json, features.json, group_predictions.csv, transaction_risks.csv,
holdout_predictions.csv, subagent_risks.csv, employee_risks.csv.
predict_saved_model загружает сохраненную модель и воспроизводит прогноз.
Алгоритм детерминированный, порог ошибки 0.5, уверенного источника 0.6.
Источник предсказывается условно при наличии ошибки. Максимум по группам
исходной строки — оценка приоритета, не калиброванная вероятность объединения.

Рейтинги учитывают исходные строки, не число билетов; показывают средний и
максимальный риск, число строк с риском от 0.5, объем и достаточность (30 строк).
Они помогают выбирать очередь проверки, не назначают персональную вину.
В Excel добавлены «Качество модели», «Риски транзакций», «Приоритет субагентов»,
«Приоритет сотрудников». Для новой разметки и обучения нужны два периода данных.
