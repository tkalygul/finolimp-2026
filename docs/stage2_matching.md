# Этап 2: сопоставление операций

```text
python reconcile_operations.py --clean interim/clean --registry interim/registry.parquet --out interim/reconciliation
python -m unittest discover -s tests -p test_stage2_matching.py
```

Модуль вызывается также из reconcile.py после очистки и загрузки реестра.
Все суммы имеют знак долга: продажа плюс, возврат/оплата минус.

## Результаты

- operation_matches.csv: группы сопоставления, суммы трех источников,
  статусы, периоды каждой системы, исходные ссылки и причины проверки.
- match_components.csv: каждая исходная строка или доля строки на билет,
  ее сумма, период, документ, создатель и ID группы сопоставления.
- matching_checks.csv: контроль количества компонентов и сохранения сумм.
- matching_summary.csv: количество групп и проверок по субагентам.

Нет слияния многие-ко-многим: каждый компонент принадлежит одной группе.
Суммы многобилетной строки делятся равномерно с сохранением полной точности.
Периоды сохраняются в компонентах: разница месяцев не означает пропуск операции.
Продажа и сервисный сбор объединяются; возврат остается отдельной группой.
Выкуп и войд сохраняются как отдельные компоненты одной продажи.
Повторные продажи/возвраты одного билета помечаются ambiguous: совпадение
суммарного оборота не доказывает совпадение отдельных событий.

Оплаты группируются по субагенту, источнику и платежному документу в пределах
близких дат. Между источниками допускается интервал до 5 суток.
Совпадение документа имеет приоритет, без него используются сумма (до 1 сома)
и даты. При нескольких кандидатах соответствие не выбирается произвольно.
Без документа раздельные суммы не объединяются автоматически: нужна проверка.

Отсутствие реестра ожидаемо только при создателе «субагент». Для бота ставится
missing_for_bot. Нераспознанная сумма реестра остается неизвестной, а не нулем.
Корпоративные и неидентифицированные записи сохраняются в отчетах этапа 1,
но не назначаются произвольному субагенту в этапе 2.

Статусы: matched, amount_difference, period_mismatch, voided, only_1c,
only_etm, only_registry, ambiguous. Дополнительные флаги amount_mismatch,
period_mismatch, registry_status и review_reason сохраняют независимые проблемы.
Это сопоставление, а не доказательство виновника или разрешение менять баланс.
Мост баланса и подписанные корректировки относятся к этапам 3 и 6.
