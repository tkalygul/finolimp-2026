# Первый этап: загрузка и контроль качества

Запуск из корня проекта:

```text
python cleaning.py data_2_final out/clean
python -m src.load_registry --data data_2_final --out interim
python -m unittest discover -s tests -p test_stage1_quality.py
```

Для загрузки реестра в Parquet нужны зависимости requirements.txt, включая pyarrow.

## Отчеты очистки

- `source_row_audit.csv`: исходные поля, номер записи CSV, источник и статус
  accepted / superseded / rejected. Каждая исходная строка 1С и ETM учтена один раз.
- `data_quality_issues.csv`: поле, исходное значение и причина отклонения.
- `subagent_name_map.csv`: исходное название и нормализованный ключ.
  review_required означает несколько написаний одного ключа; это кандидат
  на проверку, а не доказанный конфликт юридических лиц.
- `registry_source_row_audit.csv`: учет каждой строки реестра, включая строки
  без распознанных билетов. problem имеет приоритет над corporate.
- `cleaning_log.csv`: итоговые счетчики и проверки балансов.

Пустые дебет и кредит допустимы и дают ноль. Непустые неверные суммы,
отсутствующее сальдо, неверные даты, неизвестные статусы/виды/валюты/создатели,
повторные идентификаторы ETM и противоречивые шапки выбранных актов
попадают в rejected. Очистка сохраняет диагностику и завершает запуск
с ошибкой до экспорта данных для сверки. Такие строки нельзя незаметно исключить
из финансового отчета. Функции load_acts/load_etm возвращают диагностику в attrs;
при самостоятельном вызове проверяйте ее перед дальнейшими расчетами.

Статусы актов имеют приоритет: переиздан, пустой, черновик. Если несколько
версий имеют одинаковые шапки и статус, в исходных данных нет идентификатора
версии для надежного выбора. Автоматически удалять похожие проводки нельзя;
это ограничение нужно учитывать при сверке дублей на следующих этапах.

Суммы в длинных CSV распределяются между билетами в копейках, остаток получает
последний билет. Сумма исходной строки сохраняется. В реестре сохраняется полная
точность конвертации и равномерного деления; контрольный разрыв не более 1e-6 сома.
Округление для отображения не меняет исходные значения.
Поля amount_orig и amount в ETM остаются исходными суммами строки; amount_kgs
в длинном ETM теперь является суммой конкретного билета.

Нулевой войд допустим для проверки знака, но сам по себе не доказывает возврат
денег. Разрывы цепочки ETM остаются диагностикой: повторяющееся время операций
и порядок проводок требуют отдельной проверки. Этапы сверки, модель и итоговая
бухгалтерская корректировка этими изменениями не завершаются.
