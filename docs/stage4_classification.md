# Этап 4: классификация по доказательствам сверки

Основной запуск: `python reconcile.py --data data_2_final --out out/report`.
После этапов 2 и 3 классификация использует их CSV, сохраняет match_id, ссылки
на исходные записи и независимые признаки суммы, периода, дублей и реестра.

- p5_group_classification.csv — один вывод на каждую группу сверки.
- p5_balance_review.csv — отдельные случаи начальной разницы, внутреннего
  разрыва, переноса сальдо, отсутствия данных и необъясненного остатка.
- p5_classification_balance_links.csv — подписанный вклад группы по месяцу
  из этапа 3 с добавленной классификацией. Значение вклада не пересчитывается.

confidence — уровень уверенности правила, не вероятность ML.
assignment_status различает отсутствие проблемы, гипотезу и непосредственно
наблюдаемую ошибку данных. Совпадение ETM и реестра не доказывает ошибку 1С:
бот мог перенести ошибку агента. Операция только в реестре, два спорных источника,
неоднозначная оплата и повторные события требуют выяснения. Совпадение 1С и
реестра против ETM дает гипотезу ошибки бота со средней уверенностью.
Отсутствие реестра допускается только для creator=subagent или обычной оплаты.

Сумма под риском не является вкладом в баланс или корректировкой.
proposed_correction остается неизвестной: этап 4 не дает разрешения менять учет.
Балансовые диагностические случаи могут пересекаться; их суммы нельзя складывать.
Сотрудники учитываются по отдельным идентификаторам, а не строкам вида user1+user2.

Исторические функции классификации остаются для совместимости отдельных тестов
и диагностики аномалий этапа 5. Основной pipeline требует результаты сверки.
Ручной run_p5 без файлов сверки сохраняет старый режим; для строгого запуска
передавайте require_reconciliation=True. При наличии сверки обязательны также файлы этапа 3.
