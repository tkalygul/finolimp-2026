# Этап 8: запуск на новых данных и сдача

Каждый запуск создает отдельную папку out/runs/<UTC-время-ID>/interim.
Предыдущие файлы не читаются и не удаляются. Отчет и latest_run.json в корне
--out обновляются только после успешного формирования нового Excel.
Ошибка входных данных сохраняет предыдущий отчет и диагностические CSV нового запуска.

run_manifest.json фиксирует входы SHA256, версию Python/пакетов, SHA256 кода,
параметры, seed, статус ML и хеши содержательных результатов. run.log сохраняет
сообщения каждого этапа. verify_run.py проверяет целостность и совпадение
CSV/JSON двух запусков. Он не сравнивает байты XLSX: ZIP-время упаковки меняется.
При повторяемости должны совпадать данные, код, параметры и окружение.

На выгрузке одного месяца отчет сверки продолжает формироваться; MLUnavailableError
дает понятную причину, а лист «Качество модели» показывает unavailable. --skip-ml
явно отключает обучение. Ошибки схемы/ручной разметки не маскируются как нехватка истории.

Инструкция и перечень результатов приведены в README. requirements-lock.txt
фиксирует непосредственно проверенное окружение. .venv/кеши/выходы исключены из Git.
Для исторических балансов ML предпочтительна накопленная выгрузка; новая отдельная
выгрузка без исходной истории позволяет сверку за месяц, но не честную проверку ML.

Комплект для сдачи содержит код, тесты, зависимости, документацию, исходные данные
и последний успешный запуск с отчетом/моделью/метриками/признаками/рейтингами.
Презентация и текст выступления используют результаты проверенного полного запуска.
